Unified Modelling Language (UML)

What is UML?

Unified Modelling Language, often shortened to UML, is a standard way of visually modelling a system.

At Advanced Higher level, UML is used during analysis to show how users interact with a proposed system.

This page focuses on use case diagrams.

A use case diagram shows:

  • The users or external systems that interact with the system
  • The main tasks the system must support
  • The relationships between users and tasks

Use Case Diagrams

A use case diagram is used to model the functionality of a system from the point of view of the user.

It does not show program code, database tables or screen layouts.

Instead, it shows what the system must allow different users to do.

Use case diagrams are useful because they help developers understand the main functional requirements of a system.

Actors

An actor is a person, group or external system that interacts with the system.

Actors are shown outside the system boundary.

Examples of actors include:

  • Pupil
  • Teacher
  • Administrator
  • Customer
  • Payment system
  • Email system

!!! note "Important"

An actor is not always a person. It can also be another system that communicates with the system being developed.

Use Cases

A use case is a task or function that the system must carry out for an actor.

Use cases are usually written as short verb phrases.

Examples include:

  • Log in
  • Upload homework
  • View feedback
  • Search records
  • Add new user
  • Generate report

Use cases should describe what the system does, not how the code works.

System Boundary

The system boundary is a box that shows what is included inside the system being developed.

Actors are placed outside the system boundary.

Use cases are placed inside the system boundary.

This helps clearly show the difference between:

  • The system itself
  • The people or external systems that interact with it

Relationships

Relationships show how actors and use cases are connected.

The most common relationship is an association.

An association is shown using a straight line between an actor and a use case.

It means that the actor is involved in that use case.

Example

If a pupil can upload homework, a line would connect:

  • The Pupil actor
  • The Upload homework use case

Include and Extend Relationships

Some use case diagrams may show extra relationships between use cases.

Include

An include relationship is used when one use case always includes another use case.

For example:

  • Submit homework may include Log in

This means the user must log in as part of submitting homework.

Extend

An extend relationship is used when one use case may optionally add extra behaviour to another use case.

For example:

  • Apply discount may extend Checkout

This means the discount only happens in some situations.

!!! warning "Keep it Simple"

For Advanced Higher analysis, the key focus is being able to identify actors, use cases and relationships clearly.

Example Scenario

A school wants an online homework submission system.

The system should allow pupils to upload homework and view feedback. Teachers should be able to view submissions and add feedback. An administrator should be able to manage user accounts.

Possible Actors

Actor Role
Pupil Uploads homework and views feedback
Teacher Views submissions and adds feedback
Administrator Manages user accounts

Possible Use Cases

Use Case Description
Log in Allows users to access the system
Upload homework Allows pupils to submit work
View feedback Allows pupils to read teacher feedback
View submissions Allows teachers to see submitted work
Add feedback Allows teachers to comment on work
Manage accounts Allows an administrator to add or remove users

Common Mistakes

Mistake Why it is a problem
Putting actors inside the system boundary Actors are outside the system
Writing use cases as nouns only Use cases should describe actions
Including implementation details Use case diagrams show functionality, not code
Missing relationships It must be clear which actor uses which function
Adding too much detail The diagram should show the main user interactions

Summary

UML Term Meaning
Actor A person, group or external system that interacts with the system
Use case A task or function the system must provide
System boundary The box showing what is included in the system
Relationship A connection showing how actors and use cases are linked
Include A use case that always uses another use case
Extend A use case that optionally adds behaviour to another use case
