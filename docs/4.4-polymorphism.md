# Polymorphism

!!! info "What You Need to Know"

    You must be able to describe, exemplify and implement polymorphism.

## Building on Inheritance

Inheritance allows related subclasses to share properties and methods from a superclass. Sometimes each subclass needs its own version of the same action.

For example, both pupils and teachers can display details, but the details displayed are different.

## The Main Idea

```text
Person superclass
└── method: display_details()
        ▲
        │
   ┌────┴────┐
   │         │
 Pupil     Teacher
 display_  display_
 details() details()
```

Both subclasses use the same method name, but provide different implementations.

```python
class Pupil(Person):

    def display_details(self):
        print("Pupil:", self.name)


class Teacher(Person):

    def display_details(self):
        print("Teacher:", self.name)
```

This is **polymorphism**: the same method call can produce different behaviour depending on the object receiving it.

## Method Overriding

A subclass **overrides** a method by defining a new method with the same name as an inherited method.

```python
class Person:

    def display_details(self):
        print("Person:", self.name)
```

When `Pupil` defines its own `display_details()`, a pupil object uses the subclass version instead of the inherited version.

## The Same Call, Different Behaviour

```python
pupil1.display_details()
teacher1.display_details()
```

The method call has the same form each time:

```text
object.display_details()
```

The object's class determines which version runs.

## Processing Different Objects Together

The benefit becomes clearer when related objects are stored in one array:

```python
people = [pupil1, teacher1]

for person in people:
    person.display_details()
```

The loop does not need separate selection statements to determine the type of each object. It sends the same message—`display_details()`—to every object.

## Complete Working Example

```python title="Polymorphic Display Method" linenums="1"
class Person:

    def __init__(self, name):
        self.name = name

    def display_details(self):
        print("Person:", self.name)


class Pupil(Person):

    def __init__(self, name, year_group):
        super().__init__(name)
        self.year_group = year_group

    def display_details(self):
        print("Pupil:", self.name)
        print("Year group:", self.year_group)


class Teacher(Person):

    def __init__(self, name, subject):
        super().__init__(name)
        self.subject = subject

    def display_details(self):
        print("Teacher:", self.name)
        print("Subject:", self.subject)


people = [
    Pupil("Alice", 6),
    Teacher("Mrs Smith", "Computing")
]

for person in people:
    person.display_details()
    print()
```

## Inheritance Compared with Polymorphism

| Inheritance | Polymorphism |
|---|---|
| Creates a relationship between classes | Allows related objects to respond differently |
| Shares properties and methods | Uses the same method name with different implementations |
| `class Pupil(Person):` | Each subclass defines `display_details()` |

## Common Mistakes

### Using Different Method Names

Polymorphism requires a shared method name. `display_pupil()` and `display_teacher()` are two unrelated calls, not this form of polymorphism.

### Forgetting to Override the Method

If a subclass does not provide its own implementation, it uses the inherited superclass version.

### Checking Every Object Type Manually

Long `if` statements checking each object's type often defeat the purpose of polymorphism. Call the shared method and allow the object to select its implementation.
