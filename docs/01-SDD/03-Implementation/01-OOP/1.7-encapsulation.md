# Encapsulation

In the previous chapters, we learned that classes group properties and methods together. Properties store information about an object, while methods allow the object to carry out actions.

**Encapsulation** is an Object-Oriented Programming principle that groups related properties and methods inside a class and allows access to the data to be controlled.

## Why Is Encapsulation Important?

Our library system uses a `Book` class to store information about each book.

Until now, we have changed the loan status directly:

```python
book.on_loan = True
```

Although this works, it allows other parts of the program to change the value without going through the class's methods.

Encapsulation allows us to control how a property's value is accessed and changed.

For example, we can use methods to retrieve a book's loan status or update it when somebody borrows the book.

## Public and Private Members

A **public member** can be accessed from outside the class.

A **private member** is intended to be accessed only from within the class.

UML class diagrams use symbols to show visibility:

- `+` indicates a public member.
- `-` indicates a private member.

## Encapsulation in Python

Python commonly uses a leading underscore to indicate that an attribute is intended for internal use.

For example, `_on_loan` indicates that the loan status should normally be accessed through the class's methods rather than changed directly.

```python
class Book:
    def __init__(self, title, copy_number):
        self.title = title
        self.copy_number = copy_number
        self._on_loan = False
```

The underscore is a naming convention. It does not prevent other code from accessing the attribute, but it tells programmers that the attribute is intended for internal use.

## Getter Methods

A **getter method**, also called an **accessor**, returns the value of a property.

We can add the following method inside the `Book` class:

```python
def get_loan_status(self):
    return self._on_loan
```

The method returns the current loan status without changing it.

We can call it using:

```python
print(book.get_loan_status())
```

If the book is available, the output is:

```text
False
```

The program retrieves the value through the public method rather than accessing `_on_loan` directly.

## Setter Methods

A **setter method**, also called a **mutator**, changes the value of a property.

We can add the following method inside the `Book` class:

```python
def set_loan_status(self, status):
    if type(status) is bool:
        self._on_loan = status
```

The method receives a new value through the `status` parameter.

Before updating `_on_loan`, it checks that the supplied value is a Boolean.

This is an example of **validation**. It prevents an unsuitable value from being stored.

To change the loan status, we call:

```python
book.set_loan_status(True)
```

If the value passes validation, the setter updates `_on_loan` to `True`.

If the value is not a Boolean, the property remains unchanged.

## Putting It All Together

The following program demonstrates encapsulation using a getter and setter.

```python
class Book:
    def __init__(self, title, copy_number):
        self.title = title
        self.copy_number = copy_number
        self._on_loan = False

    def get_loan_status(self):
        return self._on_loan

    def set_loan_status(self, status):
        if type(status) is bool:
            self._on_loan = status


book = Book("The Hobbit", 101)

print(book.get_loan_status())

book.set_loan_status(True)

print(book.get_loan_status())
```

Output:

```text
False
True
```

When the object is created, `_on_loan` is set to `False`.

The getter returns the initial loan status.

The setter then checks the new value and changes the loan status to `True`.

The final getter call confirms that the property has been updated.

!!! info "Key Points"
    - **Encapsulation** groups related properties and methods inside a class and controls access to its data.
    - **Public members** can be accessed from outside the class and are marked with `+` in UML diagrams.
    - **Private members** are intended for internal access and are marked with `-` in UML diagrams.
    - Python uses a leading underscore as a convention for internal attributes.
    - A **getter (accessor)** retrieves a property's value.
    - A **setter (mutator)** changes a property's value.
    - Setters can include validation to prevent unsuitable values from being stored.
