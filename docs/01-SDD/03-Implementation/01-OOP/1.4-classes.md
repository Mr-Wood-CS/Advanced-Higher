# Classes

In the previous chapters, we learned that objects represent individual things in a program and store information using properties.

A library might have hundreds of books. Each book needs to store the same kinds of information, such as its title, copy number and loan status. However, the values stored by each book may be different.

Object-Oriented Programming uses **classes** to define the structure shared by these objects.

A **class** is a blueprint that defines the properties and methods that its objects will have.

## Why Do We Need Classes?

Imagine a library with 500 books. Every book needs to store three properties:

- `title` – the name of the book.
- `copy_number` – the number identifying a particular copy.
- `on_loan` – whether the book is currently borrowed.

Rather than designing each book object separately, we can define a class called `Book`.

The class provides a common structure for every book object. Each object can then store its own values for the properties defined by that class.

This helps programmers keep their code organised and consistent.

## UML Class Diagrams

A **UML class diagram** is used to show the design of a class.

A class diagram is divided into three compartments:

1. The **top compartment** contains the class name.
2. The **middle compartment** contains the properties.
3. The **bottom compartment** contains the methods.

### Understanding the Diagram

The class is named `Book`.

Its three properties are:

- `title`, which stores a string.
- `copy_number`, which stores an integer.
- `on_loan`, which stores a Boolean.

The `+` symbol indicates that a property is **public**, meaning it can be accessed from outside the class.

Notice that the diagram shows property names and data types rather than actual values.

This is an important difference between an **object diagram** and a **class diagram**.

An object diagram shows the current values stored by one particular object.

A class diagram shows the structure shared by objects created from that class.

The bottom compartment is reserved for methods, which we will explore in a later chapter.

## Defining a Class in Python

Python uses the keyword `class` to define a class.

```python
class Book:
    pass
```

Let's examine the code.

**`class`** is the Python keyword used to define a class.

**`Book`** is the name of the class. Class names normally begin with a capital letter.

**`:`** marks the beginning of the class body.

**`pass`** is a placeholder. It allows us to define the class without adding any instructions inside it yet.

At this stage, we have defined the `Book` class, but we have not created any book objects.

## Classes and Objects

It is important to understand the difference between a class and an object.

A **class** defines the structure that objects will share.

An **object** is an individual instance created from a class. Each object stores its own property values.

For example, the `Book` class can be used to create objects representing different copies of *The Hobbit*.

Although the objects share the same structure, each can have a different copy number and loan status.

!!! info "Key Points"
    - A **class** is a blueprint used to define objects.
    - A class defines the properties and methods its objects will have.
    - A **UML class diagram** shows the name, properties and methods of a class.
    - A class diagram describes structure, while an object diagram shows an object's current values.
    - Python uses the `class` keyword to define a class.
    - Defining a class does not automatically create an object.
