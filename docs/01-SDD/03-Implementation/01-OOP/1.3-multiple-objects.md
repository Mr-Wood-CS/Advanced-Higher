# Working with Multiple Objects

A library may have several copies of the same book. Although the books have the same title, each physical copy needs to be tracked separately.

For example, the library has two copies of The Hobbit. One has been borrowed, while the other is available.

The computer system represents each copy as a separate object.

## Comparing two objects

Both objects store the same three properties: title, copy_number and on_loan.

The two objects have the same property names, but their values are not necessarily the same.

- Both objects have the title "The Hobbit".

- Their copy numbers are different because they represent different physical books.
- Their loan statuses are different because only the first book has been borrowed.

This allows the library to track each copy independently.

## Object States

Each object stores its own property values. Together, these values make up the object's state.

When somebody borrows **Book: Copy Number 102**, its **On Loan** property changes from ==False== to ==True==.

Only the loan status of **Book: Copy Number 102** has changed. Its title and copy number remain the same.

**Book: Copy Number 101** is unaffected because it is a separate object with its own properties.

!!! Note

    This is an important feature of Object-Oriented Programming: changing the state of one object does not automatically change the state of another object.

## Finding Individual Objects

When a program contains several objects, it needs a way to identify which object it is working with.

An object reference allows the program to refer to a particular object.

For example, we could use:

- ==copy1== to refer to Book 101.

- ==copy2== to refer to Book 102.

These are simply names used by the program to distinguish between the two objects.

Accessing Properties in Python
Python uses dot notation to access an object's properties.

For example:
```python
print(copy1.on_loan)
print(copy2.on_loan)
```


The first line displays the loan status of Book 101. The second displays the loan status of Book 102.

The output is:

```text
True
False
```

We can also change the value of a property:

```python

copy2.on_loan = True

```

This changes the loan status of Book 102.

Book 101 remains unchanged because copy1 and copy2 refer to separate objects.

!!! warning

    The objects must already exist for this code to work. 
    
    We will learn how to create them when we study classes and instantiation.
