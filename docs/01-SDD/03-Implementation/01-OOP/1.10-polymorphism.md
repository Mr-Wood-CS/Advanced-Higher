# Polymorphism

In the previous chapters, we learned how inheritance allows subclasses to reuse and extend the properties and methods of a superclass.

Sometimes, a subclass needs to perform an inherited method differently.

**Polymorphism** allows the same method call to produce different behaviour depending on the type of object receiving it.

This is achieved through **method overriding**, where a subclass defines its own version of a method inherited from its superclass.

## Why Is Polymorphism Useful?

Our library system contains two types of books:

- `Book` represents an ordinary book.
- `AudioBook` represents an audiobook.

Both types of books need to provide a description.

However, an audiobook should also include its duration.

Rather than creating separate method names for each type of book, we can give both classes a method called `get_description()`.

Each class can then provide the appropriate description.

## Method Overriding

**Method overriding** occurs when a subclass defines a method with the same name as a method in its superclass.

When that method is called on a subclass object, Python uses the subclass version instead of the inherited version.

The following program demonstrates this using our existing classes.

```python
class Book:
    def __init__(self, title, copy_number):
        self.title = title
        self.copy_number = copy_number
        self._on_loan = False

    def get_loan_status(self):
        return self._on_loan

    def set_loan_status(self, status):
        if type(status) is bool:
            self._on_loan = status

    def get_description(self):
        return self.title + " #" + str(self.copy_number)


class AudioBook(Book):
    def __init__(self, title, copy_number, duration):
        super().__init__(title, copy_number)
        self.duration = duration

    def get_description(self):
        return self.title + " #" + str(self.copy_number) + " - " + str(self.duration) + " minutes"
```

Notice that both classes define a method called `get_description()`.

The `Book` version returns the title and copy number.

The `AudioBook` version returns the title, copy number and duration.

Because `AudioBook` defines its own version, it **overrides** the method inherited from `Book`.

## Calling the Overridden Method

We can now create an ordinary book and an audiobook.

Add the following code below the class definitions.

```python
book = Book("The Hobbit", 101)
audiobook = AudioBook("The Hobbit", 102, 680)

print(book.get_description())
print(audiobook.get_description())
```

Output:

```text
The Hobbit #101
The Hobbit #102 - 680 minutes
```

Both objects receive the same method call:

```python
get_description()
```

However, the result depends on the class of the object.

When `book.get_description()` runs, Python uses the method defined in `Book`.

When `audiobook.get_description()` runs, Python uses the overridden method defined in `AudioBook`.

This is an example of **polymorphism**.

## Using Polymorphism in a Loop

Polymorphism becomes particularly useful when a program works with several objects.

We can store different types of book objects in the same list and call the same method on each one.

Add the following code below the class definitions.

```python
books = [
    Book("The Hobbit", 101),
    AudioBook("The Hobbit", 102, 680),
    Book("1984", 103)
]

for item in books:
    print(item.get_description())
```

Output:

```text
The Hobbit #101
The Hobbit #102 - 680 minutes
1984 #103
```

### How the Loop Works

1. The list contains objects created from `Book` and `AudioBook`.
2. On each iteration, `item` refers to the next object in the list.
3. The program calls `item.get_description()`.
4. Python selects the correct method based on the object's class.
5. The description is displayed.

Notice that the loop does not need to check whether an object is a `Book` or an `AudioBook`.

The same method call works for both types of object.

This is the main benefit of polymorphism: **one method call can work with different types of objects, while allowing each type to behave appropriately**.

## Method Overriding and Polymorphism

Although the terms are closely related, they describe different things.

| Term | Meaning |
|---|---|
| Method overriding | A subclass defines its own version of an inherited method. |
| Polymorphism | The same method call produces different behaviour depending on the object receiving it. |

In our example, `AudioBook` overrides `get_description()`.

When the loop calls `get_description()` on different objects, polymorphism allows Python to use the appropriate version.

!!! info "Key Points"
    - **Polymorphism** allows the same method call to produce different behaviour depending on the object.
    - **Method overriding** occurs when a subclass defines its own version of an inherited method.
    - An overridden method has the same name as the superclass method.
    - Python selects the appropriate method based on the object receiving the call.
    - Polymorphism allows programs to work with different types of objects without checking their class each time.
    - In UML, an overridden method appears in both the superclass and subclass.
