## From Records to Objects

At Higher, you learned that a record stores all the data about one pupil together. In Python, you may have accessed its fields like this:

```python
print(pupil_record.name)
print(pupil_record.age)
print(pupil_record.registration_group)
```

The complete record represented one pupil. `name`, `age` and `registration_group` were individual fields inside it.

Object-oriented programming starts with a similar idea. It keeps the information about one pupil together, but uses some new terminology:

| Records | Object-oriented programming |
|---|---|
| A record structure defines the fields | A **class** defines the properties and methods |
| One record stores data about one pupil | One **object** represents one pupil |
| A field stores one item of data | A **property** stores one item of data |

The important new feature is that a class can also define **methods**. A method is code that performs an action using an object's properties.

## Four Ideas to Keep Separate

Consider a program that stores pupils.

The short Python examples below preview the four ideas. The syntax is broken down carefully in the numbered steps that follow.

### Class

`Pupil` is the **class**. It defines what every pupil object will store and what every pupil object will be able to do.

First, picture the class as a simple structure:

```text
Pupil class
├── property: name
├── property: year_group
└── method: display_details()
```

The same structure can then be implemented in Python:

```python
class Pupil:

    def __init__(self, name, year_group):
        self.name = name
        self.year_group = year_group

    def display_details(self):
        print(self.name, self.year_group)
```

| Tree | Python |
|---|---|
| `property: name` | `self.name` |
| `property: year_group` | `self.year_group` |
| `method: display_details()` | `def display_details(self):` |

The class is the definition. It does not represent a particular pupil.

### Object

An **object** is one particular pupil created using the class.

```python
pupil1 = Pupil("Alice", 6)
```

`pupil1` refers to the complete object—not just its name or year group.

### Property

A **property** is one item of data stored inside an object.

```python
print(pupil1.name)        # Alice
print(pupil1.year_group)  # 6
```

The object is `pupil1`. Its properties are `name` and `year_group`.

### Method

A **method** is an action defined by the class and performed through an object. For example, `display_details()` can display that object's properties.

```python
pupil1.display_details()
```

The four terms therefore describe different things:

| Term | In the pupil example |
|---|---|
| Class | The definition called `Pupil` |
| Object | One complete pupil, such as `pupil1` |
| Property | One value inside the object, such as `name` |
| Method | An action, such as `display_details()` |

## One Class Can Create Several Objects

The `Pupil` class can be used to create several separate pupil objects:

```python
pupil1 = Pupil("Alice", 6)
pupil2 = Pupil("Ben", 5)
pupil3 = Pupil("Cara", 6)
```

Each object follows the same class definition, but stores its own property values.

## Step 1 — Defining a Class with `__init__`

```python title="Add an Initialiser" linenums="1"
class Pupil:

    def __init__(self, name, year_group):
        self.name = name
        self.year_group = year_group
```

`class Pupil:` begins the class definition. The indented code underneath belongs to the class.

`__init__` is a special method that runs automatically when a new object is created. Its job is to give the new object its initial state.

The name has two underscores before and after `init`:

```text
__init__
```

It is commonly pronounced “dunder init”, meaning “double-underscore init”. You do not normally call it directly; Python calls it during instantiation.

!!! note "Initialiser and Constructor"

    `__init__` is commonly called a constructor in introductory Python. More precisely, it initialises an object after Python has created it.

## Step 2 — Understanding `self`

`self` refers to the particular object currently using the method.

```python
self.name = name
```

The two uses of `name` have different jobs:

| Code | Meaning |
|---|---|
| `name` | A parameter containing a value supplied to `__init__` |
| `self.name` | A property stored permanently inside this particular object |

The assignment copies the parameter value into the object's property.

```text
parameter                    object property
   name      ──────────────▶    self.name
```

The same happens here:

```python
self.year_group = year_group
```

Each object receives its own `name` and `year_group` properties.

!!! important "Is `self` a Keyword?"

    `self` is not a reserved Python keyword, but it is the standard name used for the current object. Using a different name would be confusing and should be avoided.

## Step 3 — Instantiating an Object

**Instantiation** means creating an object from a class.

```python title="Create One Object" linenums="1"
pupil1 = Pupil("Alice", 6)
```

This statement causes Python to:

1. create a new `Pupil` object
2. call its `__init__` method automatically
3. pass `"Alice"` into the `name` parameter
4. pass `6` into the `year_group` parameter
5. store the completed object in `pupil1`

Although `__init__` declares three parameters, only two arguments are written when the object is created:

```python
def __init__(self, name, year_group):
    ...
```

```python
pupil1 = Pupil("Alice", 6)
```

Python supplies `self` automatically. In this call, `self` refers to the new object that will be stored in `pupil1`.

| Parameter | Value received |
|---|---|
| `self` | The new `Pupil` object—supplied automatically |
| `name` | `"Alice"` |
| `year_group` | `6` |

## Step 4 — Creating Multiple Objects

```python title="Create Separate Objects" linenums="1"
pupil1 = Pupil("Alice", 6)
pupil2 = Pupil("Ben", 5)
```

Both objects follow the same class definition, but each has its own data:

| Object | `name` | `year_group` |
|---|---|---:|
| `pupil1` | Alice | 6 |
| `pupil2` | Ben | 5 |

Changing one object does not change the other:

```python
pupil1.year_group = 7

print(pupil1.year_group)  # 7
print(pupil2.year_group)  # 5
```

## Step 5 — Accessing Properties

Use **dot notation** to access a property:

```python title="Access Object Properties" linenums="1"
print(pupil1.name)
print(pupil1.year_group)
```

```text
object.property
pupil1.name
```

The dot separates the object name from the property being accessed.

## Step 6 — Adding a Method

A **method** is a subprogram defined inside a class. It describes behaviour belonging to the objects created from that class.

```python title="A Class with a Method" linenums="1"
class Pupil:

    def __init__(self, name, year_group):
        self.name = name
        self.year_group = year_group

    def display_details(self):
        print("Name:", self.name)
        print("Year group:", self.year_group)
```

`display_details()` has a `self` parameter because it needs to access the properties of the object that calls it.

Call the method using dot notation:

```python title="Call an Object Method" linenums="1"
pupil1 = Pupil("Alice", 6)
pupil1.display_details()
```

Python automatically passes `pupil1` into the method as `self`. Conceptually, the call behaves like:

```python
Pupil.display_details(pupil1)
```

You should normally use the clearer dot-notation version:

```python
pupil1.display_details()
```

## How `self` Selects the Correct Object

```python title="The Same Method, Different Objects" linenums="1"
pupil1 = Pupil("Alice", 6)
pupil2 = Pupil("Ben", 5)

pupil1.display_details()
pupil2.display_details()
```

During the first call, `self` refers to `pupil1`, so the method displays Alice's properties. During the second call, `self` refers to `pupil2`, so it displays Ben's properties.

The method is written once but works with whichever object calls it.

## Complete Working Example

```python title="Pupil Class and Objects" linenums="1"
class Pupil:

    def __init__(self, name, year_group):
        self.name = name
        self.year_group = year_group

    def display_details(self):
        print("Name:", self.name)
        print("Year group:", self.year_group)


pupil1 = Pupil("Alice", 6)
pupil2 = Pupil("Ben", 5)

pupil1.display_details()
print()
pupil2.display_details()
```

Output:

```text
Name: Alice
Year group: 6

Name: Ben
Year group: 5
```

## Common Mistakes

### Missing `self` from a Method Definition

```python
# Incorrect
def display_details():
    print(self.name)
```

Instance methods must declare `self` as their first parameter:

```python
# Correct
def display_details(self):
    print(self.name)
```

### Forgetting `self.` When Creating a Property

```python
# This creates only a temporary local variable.
name = name
```

To store the value in the object, use:

```python
self.name = name
```

### Calling a Method Without Parentheses

```python
# Refers to the method but does not call it.
pupil1.display_details

# Calls the method.
pupil1.display_details()
```

### Supplying the Wrong Number of Arguments

```python
# Missing the year_group argument.
pupil1 = Pupil("Alice")
```

The arguments supplied during instantiation must match the parameters declared after `self` in `__init__`.

## Key Vocabulary

| Term | Meaning |
|---|---|
| Class | A definition or blueprint used to create objects |
| Object | One instance of a class |
| Property | Data stored in an object |
| Method | A subprogram defined inside a class |
| Instantiation | Creating an object from a class |
| `__init__` | Special method that initialises a new object |
| `self` | A reference to the object currently using a method |
| Dot notation | Syntax used to access an object's properties and methods |
